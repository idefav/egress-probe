# Browser WebRTC checks

The Avalonia Proxy check toolbar has a separate **Browser WebRTC** action. Configure the independent observer and its memory-only API credential first. The action starts a new report, opens the default browser, and runs 1–3 samples. Keep the page open. Cancel in v2rayN deletes the session; the server closes its peers. A run times out after 165 seconds and is cancelled if the running core or routing configuration changes.

This is real `RTCPeerConnection` ICE → DTLS → SCTP DataChannel traffic, not a native STUN request presented as a browser result. No camera, microphone or media permission is requested. The server uses Pion with one UDP 3480 ICE mux, IPv4 ICE-lite and its public NAT address. Existing control and web page traffic uses certificate-validated HTTPS 443. Existing authenticated STUN 3478 is not usable as a browser ICE server because browsers cannot attach the private probe attribute.

When upgrading an existing systemd installation, also update the service unit and run `systemctl daemon-reload` before restarting the observer. ICE interface enumeration requires `AF_NETLINK` in `RestrictAddressFamilies`. Without it, public signaling returns `failed to create network: route ip+net: netlinkrib: address family not supported by protocol`, although ordinary socket probes still work. The unit retains the dedicated non-root account and only `CAP_NET_BIND_SERVICE`; it does not grant `CAP_NET_ADMIN`.

The browser sends its short-lived probe ID and nonce inside the data channel. The server signs the selected ICE remote IP/port. A successful result requires the browser to receive that receipt and echo it through the authenticated short-lived signaling channel. v2rayN independently verifies the pinned P-256 signature and probe identity, then compares the actual IP against `api.<domain>:3480|webrtc|browser`, host or global IP/CIDR expectations. Without an expectation, the result records the observed IP and does not claim a match.

Candidate summaries and browser identity are explicitly **browser-reported, unsigned evidence**. A host candidate is not proof of public IP leakage. A `.local` candidate masks a host address with mDNS. The page deliberately uses no third-party STUN or TURN provider: this checks the real path to the independent public ICE peer. It does not inventory every possible server-reflexive candidate from external STUN providers. TURN relay behavior, IPv6 WebRTC transport, media traffic, other browser profiles and browser DoH remain outside coverage.

Only short-lived tickets and the public signing key go into the launch URL fragment; the page removes the fragment immediately. The permanent API key is never passed to the browser. SDP, ICE credentials and permanent credentials are excluded from reports. The page has no external scripts, no referrer and a restricted CSP. Signaling requires TLS, same-origin requests and a valid nonce-bound WebRTC ticket. Offers are single-use, bounded to 64 KiB; reports are bounded to 16 KiB; at most four peers and 128 retained statuses are allowed. Private, loopback and link-local remote ICE candidates are filtered in production. Fixture-only loopback is enabled only in tests. Ticket expiration, session deletion and server shutdown release peers.

Run `go test -race ./...` for a real Pion-to-Pion loopback fixture covering ICE/DTLS/SCTP, exact receipt echo, invalid origin/nonce/SDP, fabricated completion, replay and session cleanup. v2rayN `WebRtcTests` covers signed protocol binding, CIDR rules, wrong exits and the separation of candidate claims from signed egress. Public browser acceptance must be recorded separately; protocol fixtures alone do not prove browser compatibility or cloud UDP ingress.
